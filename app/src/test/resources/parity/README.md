# Фикстуры паритета клиентов

Один и тот же набор кейсов гоняют **все** реализации клиентского ядра:

| Платформа | Где тесты | Откуда берут фикстуру |
|---|---|---|
| Windows | `win-app/D1Vision.Tests/` | читают этот каталог напрямую |
| macOS + iOS | `mac-app/LampaKit/Tests/LampaKitTests/` | копия в `Fixtures/parity/` (SPM не умеет ресурсы вне пакета) |
| Android | `E:\LAMPA-App\app\src\test\resources\parity\` | копия (отдельный git-репозиторий, сьюта обязана быть автономной) |

**Копии синхронизирует `scripts\test-all.ps1 -SyncFixtures`.** Без флага гейт сверяет SHA-256
каждой копии с каноном и падает при расхождении — иначе разъехаться могла бы сама фикстура,
и паритет перестал бы что-либо доказывать.

## Зачем это нужно

Одна и та же логика написана трижды — на Swift, C# и Kotlin. Расхождение не ловится ничем:
каждая реализация по отдельности «работает». Реальный пример, найденный при заведении этих
тестов: `isPrivateIP` на Swift и C# проверял `127.` префиксом, а на Kotlin — точным равенством
`127.0.0.1`. Адрес `127.0.0.2` три клиента классифицировали по-разному.

## Формат

У каждого кейса есть поле `platforms`: либо `"*"` (обязателен всем), либо список тех, кто
обязан его проходить. Осознанные расхождения выносятся в раздел `divergences` **с причиной** —
молча выпасть из проверки кейс не может.

## Файлы

| Файл | Что фиксирует |
|---|---|
| `d1v-hosts.json` | `isOurHost` / `isPrivateIP` — какие хосты «наши» |
| `d1v-sign.json` | `sign()` — куда дописывается ключ периметра и куда нет |
| `d1v-navigation.json` | `isAllowedNavigation` — какие схемы открываются в оболочке |
| `host-race.json` | Гонка хостов: кто побеждает при каких задержках |
| `ua.json` | User-Agent и формат версии («4 замка» маршрутизации плеера) |
| `bridge-roster.json` | 22 метода моста `window.AndroidJS` |
| `player-thresholds.json` | Пороги плеера и восстановления потока |
